# Files listed here implement a vendor adapter that requires a proprietary
# SDK or physical/emulated HSM hardware unavailable in CI.
# ci/coverage.sh excludes them from the coverage floor computed here.
#
# This is not a lower bar: it is a different, more honest one. Coverage is a
# CI-computed number, and CI cannot execute code it has no way to run — a
# blanket floor over the whole package would either block merges on lines
# that will never run in CI, or get quietly lowered until it protects
# nothing. Excluding these files keeps the floor meaningful for the code CI
# actually exercises. The adapters listed here are instead validated by the
# conformance suite passing against ProtectToolkit-C software emulation and
# against a Luna Network HSM 7 in the maintainer's own environment, and that
# claim is labelled maintainer-verified, not CI-verified, everywhere it is
# made.
#
# When the nShield adapter arrives with the same constraint, add its file
# here. This list is the single place that decision lives.
pkcs11/protectserver.go
pkcs11/luna.go
#
# internal/hsmtest is test scaffolding that has to be a package rather than a
# _test.go file, because Go cannot share test helpers across packages. It is
# not product code, so it does not belong in a product-code coverage figure —
# and its per-vendor setup paths are unreachable in CI for exactly the reason
# above: no ProtectServer, no nShield, no Luna. Counting it dropped the
# reported number from 79.6% to 75.0% while nothing about the product's
# tested-ness changed, which is precisely the distortion this file exists to
# prevent.
internal/hsmtest/hsmtest.go
#
# pkcs11/conformance is the same kind of scaffolding, exported so that a
# module outside this repository can run the suite against its own token.
# pkcs11/conformance_test.go runs it here, and the coverage that run
# produces is counted where the code under test lives, in pkcs11.
pkcs11/conformance/conformance.go
